# culdcept_saturn_tools

Tools for Sega Saturn's game  "Culdcept" : translation and hacks.

## Repo content

It contains scripts to extract Japanese text and reinject it after translation into the disc image of the Culdcept. It also contains preliminary elements for building a card editor.

My initial motivation was to translate this game, which has an untranslated 4-player option. I also wanted to explore how Python handles byte manipulation. For the latter, the conclusion is that “it’s ok,” but not the most well-documented possibility. I also had lots of fun using regexp-based byte pattern fishing. 🤪

I decided to interrupt this project following the announcement of Culdcept The First, part of the Saturn Tribute series. Best regards to the company and developers who revived and translated this old game.

Still, I learned a lot about Saturn hacking, and in this repository you will find everything that I produced. I also uploaded a few JSON files containing low-quality translations, just as a proof of concept.

## Features
The scripts allow the following tasks to be performed:

* Shift-JIS script extraction to JSON-formatted outputs, which include:
  * Main scenario
  * Character taunts
  * Tutorials
  * Cards/items
  * Help script
  * Shrine effects
  * Optional extraction of card statistics
* Translated text reinjection:
  * By parsing the edited JSON files, the script will look for translated text blocks and ignore untranslated fields.
  * It will patch the `CULDCEPT.DT0` file, which should first be extracted from the game disc image (this file contains all texts).
  * There are some basic tests to verify that the translation can fit into the limited number of bytes (see below for current limitations).
* Necessary post-processing : once patched, the CULDCEPT.DT0_patched file generated by the script should be:
    * Renamed CULDCEPT.DT0
    * Reinserted into the disc image using Sega Saturn Patcher to build a patched disc image or a SSP patch file (confirmed working with version 1.9.7872.1316).

## What remained to be done / current limitations :

* Extraction of non-Shift-JIS texts is not yet implemented.
* Zero graphic hacks.
* No work on variable-width font hacks.
* No work on menu and name-entry screens.
* Card statistics can be extracted, but I did not write the lines necessary to reinject them after modification. However, developing a card editor tool seems like a relatively easy task.
* Offset table recomputation:
  * Currently, translations have to fit into a restricted number of bytes inherited from the original text.
  * Allowing longer translated texts is possible, but will require implementing offset table update computations. That should be easy for the main scenario, taunts, and tutorials, as far as I can tell, because these text blocks do not contain specific pointers to other elements. However, the data structure is more complex for the help script (e.g. menus), cards, etc., and table/pointer updates will require deeper analysis before allowing text extensions.

Finally, it is worth mentioning that this game has only 3 files on the disc!

* The `BIN` file contains libraries and code, as well as the fonts (in the very last bytes).
* The `DT0` file contains texts, assets, and other content data. A large proportion consists of sprites and tiles.
* The `DT1` file likely contains the videos and sound effects (not verified).

This makes shifting bytes in DT0 difficult, because all offset tables in the file need to be updated, meaning that the whole file and assets should probably be documented. For instance, the very beginning has a table pointing to, as far as I can tell, subsections of assets (background tiles, opponent texts, and interleaved sprites).

## Usage

Be aware that two disc versions are referenced by Redump. All scripts should be applied to the following disc, which is v1.04.

I did not test whether the offsets are still valid for the other version, v2.0. Scripts may require some updates, at least in terms of offsets.

1. From the disc image, extract the CULDCEPT.DT0 file.
2. Update the variable `_DT0` in the `meta.py` file with the path to your extracted DT0 file.
3. Run any of the following scripts to extract texts from the corresponding sections. An output directory named translations, containing one or more JSON files, will be generated.
  * `scenario_extraction.py` (one JSON per scenario block)
  * `help_script_extraction.py` (one JSON per block)
  * `cards_extraction.py` (one JSON for all; a Boolean variable also allows card statistics to be extracted to the JSON)
  * `tutorials_extraction.py` (one JSON for all)
  * `taunts_extraction.py` (one JSON per opponent)
  * `shrine_effects.py` (one JSON for all)

4. In the generated JSON files, the only interesting fields for translation are `original_txt` (what was extracted) and `translated_txt` (empty; add translations there). You can have a look to the few json in the `translation` directory of the repo to get a glimpse of their content. Do not modify the other fields, as they will be used for patching. The ruler_helper field shows how many characters are available per line (- is a character, | is a line return). Its only purpose is to help with the alignment of translated text using any basic text editor. 

5. (optionnal) The repository contains a “dirty” translation for demonstration purposes in the `translations` directory. It is limited to the start of the scenario, the taunts of the first opponent, some parts of the help script (press the L button in any menu to display help), and very very few cards.

6. After filling some of the `translated_txt` fields, run the script `patcher.py`. It will detect all translated fields and inject the corresponding text bytes. If a translated field generates too many bytes compared to what can be injected, it will highlight the corresponding field and request a shorter text modification (including how much it should be reduced).

## Documentation

The headers of all `*_extraction.py` files describe how the text is encoded and the corresponding byte-level structures.

They also describe how offset tables and pointers work. This can differ significantly from one type of object to another (scenario, taunts, cards, etc.), which explains my type-specific text extraction approach.

I also started a tutorial on the SegaXtreme forum, hoping it will help newcomers interested in translation work: https://segaxtreme.net/threads/translating-culdcept-tutorials-notes-whatever.25559/
